# TaihuCasino Follow-Up Documentation Index v1.0 / 太湖赌场后续文档目录 v1.0

Date / 日期：`2026-04-06`  
Audience / 适用对象：TaihuCasino 5-8 person team / TaihuCasino 5-8 人团队

## Purpose / 目的

This index extends the product charter into executable, verifiable, and collaborative documentation.

本目录用于承接产品宪章，将方向、边界和判断原则转化为可执行、可验证、可协作的后续文档。

The charter defines direction and boundaries. Follow-up documents should translate those principles into concrete working materials without changing the charter itself.

宪章负责定义方向与边界；后续文档负责把这些原则转化为具体工作材料，但不应修改宪章本身。

## 1. MVP Scope And Acceptance Criteria v1.0 / MVP 范围与验收标准 v1.0

Priority / 优先级：P0

Goal:

目标：

Define the functional boundary, non-functional requirements, acceptance criteria, and launch gate for the first version.

把宪章中的“必做范围”和“优先级原则”转化为首个版本的功能边界、非功能要求、验收口径与上线闸门。

## 2. Experience Style Guide v1.0 / 体验风格规范 v1.0

Priority / 优先级：P0

Goal:

目标：

Constrain visual design, interaction, sound, and copy so the product remains premium, restrained, Taihu-like, and low-noise in actual delivery.

约束视觉、交互、声音与文案的一致性，确保“高端克制、太湖气质、低噪音节奏”能在实际产出中被执行。

## 3. Monetization Constraint Details v1.0 / 商业化约束细则 v1.0

Priority / 优先级：P1

Goal:

目标：

Detail rewarded ads, IAP, recovery mechanics, and free-player sustainability rules so monetization does not drift away from the charter.

细化广告、IAP、破产恢复、免费玩家可持续游玩等规则，避免商业化在实现过程中偏离宪章。

## 4. Event Tracking And Metrics Definitions v1.0 / 埋点与指标定义 v1.0

Priority / 优先级：P1

Goal:

目标：

Define unified metrics such as valuable session length, retention, math-module participation, and non-betting dwell time for later analysis and review.

将“有价值时长”、留存、数学模块参与率、非下注停留时长等指标定义为统一的数据口径，用于后续分析与复盘。

## 5. Feature Proposal Checklist v1.0 / 功能提案检查表 v1.0

Priority / 优先级：P1

Goal:

目标：

Turn feature gates and charter alignment checks into a lightweight template for product, design, and engineering review.

把 Feature Gate 和宪章对齐检查变成轻量模板，供产品、设计、研发在新功能评审时直接使用。

## Usage Principles / 使用原则

- The charter has priority over all follow-up documents.  
  宪章优先于所有后续文档。
- Follow-up documents may refine execution details but must not modify charter boundaries.  
  后续文档可以细化执行口径，但不得修改宪章边界。
- If a follow-up document conflicts with the charter, revise the follow-up document first.  
  如果后续文档与宪章冲突，应优先修订后续文档，而不是绕过宪章。
- Add new specialized documents only when team size or system complexity makes them necessary.  
  只有当团队规模或系统复杂度明显提升时，才增加新的专项文档。
